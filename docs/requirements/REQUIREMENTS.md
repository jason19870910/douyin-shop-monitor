# 需求规格说明书（Requirements Specification）

## 1. 功能需求
| 编号 | 功能描述 | 优先级 |
|---|---|---|
| FR-001 | 定时抓取商品数据并持久化 | 高 |
| FR-002 | 定时抓取订单数据并持久化 | 高 |
| FR-003 | 定时抓取创作者数据并持久化 | 高 |
| FR-004 | 提供商品、订单、创作者查询 RESTful API | 高 |
| FR-005 | 提供仪表盘统计接口 `/api/dashboard/stats` | 高 |
| FR-006 | 支持手动同步 `/api/sync` | 中 |
| FR-007 | 告警阈值配置查询/更新 API | 中 |
| FR-008 | 邮件/企业微信告警发送（可选） | 低 |
| FR-009 | 前端页面展示关键指标、列表、搜索、分页 | 高 |
| FR-010 | 前端告警配置页面 | 中 |

## 2. 非功能需求
| 编号 | 非功能需求 | 说明 |
|---|---|---|
| NFR-001 | 可用性 | 系统每日 99.5% 以上可用，单实例部署，需监控报警。
| NFR-002 | 性能 | API 响应时间 ≤ 200ms（除大数据导出外），数据抓取间隔可配置（默认 60 分钟）。
| NFR-003 | 可扩展性 | 通过 Docker compose 支持水平扩容，后续可接入 Kubernetes。
| NFR-004 | 安全性 | 所有敏感信息通过 .env 管理，API 通过 Token 鉴权（可选）。
| NFR-005 | 可靠性 | 抓取失败记录日志并重试，告警阈值失效时发送通知。
| NFR-006 | 可维护性 | 代码遵循 PEP8/Black，单元测试覆盖率 ≥ 80%。
| NFR-007 | 可移植性 | 支持在 Windows、Linux 环境运行，使用跨平台依赖。

---
> 需求在项目迭代中可通过变更管理流程进行增删。
