# 安全架构设计文档

## 1. 概述
本文档定义抖音电商数据监控平台的安全架构，遵循**纵深防御**、**最小权限**、**零信任**原则，覆盖网络、应用、数据、运维全生命周期。

### 2.1 网络访问控制矩阵
| 来源区域 | 目标区域 | 协议/端口 | 访问控制 |
|---------|---------|----------|---------|
| Internet | Nginx | TCP/443 | WAF + 限流 + 地理封禁 |
| Nginx | Flask API | TCP/5000 | 内网仅允许 Nginx IP |
| Flask API | MySQL | TCP/3306 | 仅允许 API 服务器 IP，账号最小权限 |
| Flask API | Redis | TCP/6379 | 仅允许 API/Worker IP，ACL 认证 |
| Celery Worker | MySQL | TCP/3306 | 仅允许 Worker IP，只读/写分离账号 |
| Celery Worker | Redis | TCP/6379 | 仅允许 Worker IP |
| 运维堡垒机 | 所有服务器 | TCP/22, 3306, 6379 | MFA + 审计录像 |
| 监控系统 | 所有服务 | TCP/9090, 9100, 8080 | 仅内网，mTLS |
| 外部 API | Internet | TCP/443 | 仅允许业务域名，证书校验 |

## 3. 身份认证与授权

### 3.1 认证体系
```
┌─────────────────────────────────────────────────────────────┐
│                      统一认证网关                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │   用户登录    │  │   API 密钥    │  │   服务间      │       │
│  │  (账号/密码)  │  │  (AK/SK)      │  │  认证 (mTLS)  │       │
│  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘       │
└─────────┼──────────────────┼──────────────────┼───────────────┘
          ▼                  ▼                  ▼
┌─────────────────────────────────────────────────────────────┐
│                      Token 服务 (JWT + Redis)                │
│  • Access Token: 30min 过期，RS256 签名                      │
│  • Refresh Token: 7天 过期，存储 Redis，支持撤销             │
│  • 服务间 Token: mTLS 证书 + SPIFFE ID                       │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 RBAC 权限模型
| 角色 | 权限范围 | 数据范围 |
|------|---------|---------|
| 超级管理员 | 全部权限 | 全部店铺 |
| 运营经理 | 读/写/告警配置/导出 | 负责店铺 |
| 运营专员 | 读/导出 | 负责店铺 |
| 业务分析师 | 读/导出 | 全部店铺 (脱敏) |
| 技术运维 | 读/部署/监控/日志 | 全部 (无业务数据权限) |
| 开发人员 | 读 (测试环境) | 测试数据 |
| 审计员 | 只读审计日志 | 全部 |

### 3.3 API 级权限控制
```python

@require_permission("order:export", scope="shop")
def get_products(shop_id: int):
    # 自动校验用户是否有该店铺权限
    pass
```

## 4. 数据安全

### 4.1 数据分级分类
| 数据类别 | 密级 | 加密要求 | 访问控制 | 保留期限 |
|---------|------|---------|---------|---------|
| 用户凭证 (Cookie/Token) | 绝密 | 传输加密 + 存储加密 (AES-256-GCM) | 仅同步服务可读 | 永久 (轮换) |
| 个人隐私 (手机/邮箱/姓名) | 机密 | 传输加密 + 存储脱敏 | 按需最小权限 | 业务需要期间 |
| 业务数据 (订单/商品/销量) | 内部 | 传输加密 | RBAC 控制 | 3 年 |
| 审计日志/操作日志 | 内部 | 传输加密 + 存储完整性 | 仅审计员 | 1 年 |
| 监控指标/性能数据 | 公开 | 传输加密 | 全员可读 | 30 天 |

### 4.2 加密方案
| 场景 | 算法 | 密钥管理 |
|------|------|----------|
| HTTPS 传输 | TLS 1.3, ECDHE_RSA_AES_256_GCM | Let's Encrypt / 内部 CA |
| 敏感配置存储 | AES-256-GCM | HashiCorp Vault / KMS |
| 数据库透明加密 | TDE (AES-256) | 云厂商 KMS |
| 备份加密 | AES-256-GCM | 独立密钥，离线存储 |
| 服务间通信 | mTLS (X.509) | SPIFFE/SPIRE 自动轮换 |

### 4.3 数据脱敏规则
| 字段 | 脱敏规则 | 适用场景 |
|------|---------|---------|
| 手机号 | `138****1234` | 列表页、导出、日志 |
| 姓名 | `张**` | 列表页、导出、日志 |
| 身份证 | `110101********1234` | 仅内部审计可见 |
| Cookie/Token | `***MASKED***` | 日志、错误堆栈、监控 |
| 金额 | 原值 (内部) / 脱敏 (外部) | 根据角色动态 |

## 5. 应用安全

### 5.1 安全编码规范 (OWASP Top 10 防护)
| 风险 | 防护措施 | 验收标准 |
|------|---------|---------|
| A01: 访问控制失效 | RBAC + 资源级权限校验 | 所有 API 强制鉴权，集成测试覆盖 |
| A02: 加密失效 | TLS 1.3 强制、敏感字段加密存储 | SSL Labs A+ 评级 |
| A03: 注入攻击 | 参数化查询、ORM、输入验证 | SAST 扫描 0 高危 |
| A04: 不安全设计 | 威胁建模、安全设计评审 | 设计文档含威胁分析 |
| A05: 安全配置错误 | 基线核对、自动化合规扫描 | CIS Benchmark 合规 |
| A06: 易受攻击组件 | 依赖扫描、SBOM、定期更新 | Dependabot/Snyk 0 Critical |
| A07: 身份认证失效 | MFA、强密码策略、会话管理 | 密码策略强制、会话固定防护 |
| A08: 软件/数据完整性 | 供应链安全、签名验证 | 镜像签名、依赖校验和 |
| A09: 日志监控失效 | 结构化日志、实时告警、审计追踪 | 关键操作 100% 有审计日志 |
| A10: SSRF | URL 白名单、内网访问限制 | 外部请求仅允许业务域名 |

### 5.2 前端安全
| 措施 | 实现 |
|------|------|
| CSP 策略 | `script-src 'self' 'unsafe-inline' https://cdn.example.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; connect-src 'self' https://api.example.com; frame-ancestors 'none';` |
| XSS 防护 | React 默认转义、危险 HTML 白名单、DOMPurify |
| 点击劫持 | `X-Frame-Options: DENY` |
| MIME 嗅探 | `X-Content-Type-Options: nosniff` |
| 引用策略 | `Referrer-Policy: strict-origin-when-cross-origin` |
| 权限策略 | `Permissions-Policy: geolocation=(), microphone=(), camera=()` |

### 5.3 后端安全
| 措施 | 实现 |
|------|------|
| 参数校验 | Pydantic / Marshmallow Schema 校验所有入参 |
| SQL 注入 | SQLAlchemy ORM + 参数化查询，禁用原生 SQL |
| 命令注入 | 禁用 `shell=True`，使用 `shlex.quote` |
| 路径遍历 | `secure_filename`、路径规范化、白名单 |
| 文件上传 | 类型校验、大小限制、存储隔离、病毒扫描 |
| 速率限制 | Redis 滑动窗口，IP + 用户双维度 |
| 错误处理 | 统一错误码、不泄露堆栈、通用错误页 |

## 6. 运维安全

### 6.1 基础设施安全
| 组件 | 加固措施 |
|------|---------|
| Linux 主机 | CIS Benchmark Level 1、禁用 root 登录、SSH 密钥认证、fail2ban |
| Docker | 非 root 用户、只读根文件系统、Capability 最小化、镜像签名验证 |
| Kubernetes (如用) | RBAC、NetworkPolicy、PodSecurityPolicy、Seccomp、Admission Controller |
| Nginx | 隐藏版本号、限制请求大小、禁用不安全方法、OCSP Stapling |
| MySQL | 账号最小权限、审计日志、SSL 连接、禁用 LOCAL INFILE |
| Redis | ACL 用户认证、bind 内网 IP、rename 危险命令、RDB/AOF 加密 |

### 6.3 事件响应流程
| 级别 | 定义 | 响应时限 | 升级路径 |
|------|------|---------|---------|
| P0 - 紧急 | 数据泄露、核心服务被攻陷、勒索软件 | 15 分钟 | 安全负责人 → CTO → 法务/公关 |
| P1 - 高危 | 关键漏洞利用、异常大量访问、权限提升 | 1 小时 | 安全团队 → Tech Lead |
| P2 - 中危 | 可疑登录、配置漂移、证书即将过期 | 4 小时 | 运维团队 |
| P3 - 低危 | 合规偏差、日志异常、扫描发现 | 24 小时 | 相关 Owner |

## 7. 合规要求

### 7.1 适用法规标准
- 《网络安全法》 / 《数据安全法》 / 《个人信息保护法》
- GB/T 35273-2020 个人信息安全规范
- ISO 27001 信息安全管理体系
- 等保 2.0 三级要求 (如适用)
- PCI DSS (如涉及支付数据)

### 7.2 合规控制点
| 控制域 | 关键控制点 | 验证频率 |
|-------|-----------|---------|
| 访问控制 | 权限定期复核、离职即时回收 | 季度 |
| 数据保护 | 敏感数据清单、加密验证、脱敏测试 | 半年 |
| 运维安全 | 变更管理、漏洞管理、基线核对 | 月度 |
| 事件管理 | 应急预案演练、溯源能力验证 | 半年 |
| 供应链 | 依赖扫描、镜像签名、第三方评估 | 持续 |

## 8. 安全监控与审计

### 8.1 关键监控指标
| 指标 | 数据源 | 告警阈值 | 响应动作 |
|------|-------|---------|---------|
| 登录失败率 | Nginx/Auth 日志 | > 5%/5min | 封禁 IP、通知运维 |
| 权限拒绝次数 | API 网关日志 | > 100/5min | 分析攻击模式 |
| SQL 错误率 | DB 审计日志 | > 1%/5min | 检查注入攻击 |
| 敏感操作审计 | 应用审计日志 | 实时 | 违规即时告警 |
| 证书过期天数 | 证书管理系统 | < 30 天 | 自动续期 + 通知 |
| 漏洞扫描结果 | 依赖扫描/镜像扫描 | Critical > 0 | 阻断发布、强制修复 |
