# Code Review 检查清单

## 使用说明
- **适用范围**: 所有合并到 `main`/`develop`/`release/*` 分支的 Pull Request
- **审查方式**: 至少 1 名 Reviewer Approve，核心模块需 2 名
- **自动化门禁**: CI 必须通过 (Lint、Test、Build、Security Scan)
- **清单使用**: Reviewer 逐项勾选，发现问题在 PR 评论中标注行号和建议
- **例外处理**: 紧急热修复可简化流程，事后补全 Review

## 1. 设计与架构

### 1.1 需求对齐
- [ ] 变更是否完整解决了 Issue 描述的问题？
- [ ] 是否引入了不必要的功能/复杂度 (YAGNI 原则)？
- [ ] 设计是否与现有架构一致 (分层、模块边界、依赖方向)？
- [ ] 是否有更简单/更标准的替代方案？

### 1.2 接口设计
- [ ] API 设计是否遵循 RESTful/GraphQL/gRPC 规范？
- [ ] 请求/响应结构是否规范 (分页、错误码、版本控制)？
- [ ] 是否考虑了向后兼容性 (Breaking Change 需版本号/迁移指南)？
- [ ] 是否有完整的 API 文档更新 (OpenAPI/Swagger)？

### 1.3 数据模型
- [ ] 数据库 Schema 变更是否有迁移脚本 (Up/Down 可回滚)？
- [ ] 索引设计是否合理 (覆盖查询模式、避免冗余)？
- [ ] 是否考虑了数据一致性 (事务边界、分布式事务、最终一致性补偿)？
- [ ] 敏感字段是否加密/脱敏 (PII、凭证、Token)？

### 1.4 安全设计
- [ ] 认证授权检查是否完整 (资源级权限、所有权校验)？
- [ ] 输入验证是否全面 (参数校验、长度限制、类型约束、白名单)？
- [ ] 是否防范常见漏洞 (SQL 注入、XSS、CSRF、SSRF、路径遍历、命令注入)？
- [ ] 敏感操作是否有审计日志 (操作人、时间、前后值、IP)？
- [ ] 密钥/Token 是否硬编码 (应使用 Vault/环境变量)？

## 2. 代码实现质量

### 2.1 通用编码规范
- [ ] 代码风格符合项目规范 (Lint 通过、格式化工具格式化)
- [ ] 命名规范统一 (变量/函数/类/常量/文件)，语义清晰，无拼写错误
- [ ] 函数/方法单一职责，长度适中 (建议 < 50 行)，圈复杂度低 (< 10)
- [ ] 无重复代码 (DRY)，公共逻辑已抽象复用
- [ ] 错误处理完善 (统一错误码、错误信息可读、堆栈保留、不吞异常)
- [ ] 日志规范 (级别正确、结构化、含 Trace ID、不打印敏感信息)
- [ ] 注释必要且准确 (公共 API 必须、复杂逻辑说明、TODO 规范格式)

### 2.2 语言特定规范

#### Python (Backend)
- [ ] 类型注解完整 (参数、返回值、类属性)，`mypy --strict` 通过
- [ ] 依赖管理规范 (`requirements.txt`/`pyproject.toml` 锁定版本、无冲突)
- [ ] 异步代码正确使用 `async/await`、无阻塞调用、连接池复用
- [ ] 数据库查询使用 ORM/参数化，无 N+1 问题、大事务拆分
- [ ] Celery 任务幂等、可重试、超时设置、结果后端配置
- [ ] 测试覆盖核心逻辑，`pytest` 通过、覆盖率达标

#### TypeScript/React (Frontend)
- [ ] 严格模式 `strict: true` 通过，无 `any` 滥用
- [ ] 组件设计合理 (展示/容器分离、Props 类型定义、默认值)
- [ ] Hooks 使用规范 (依赖数组完整、无 stale closure、自定义 Hook 复用)
- [ ] 状态管理清晰 (Context/Redux/Zustand 选型合理、最小化全局状态)
- [ ] 性能优化到位 (`React.memo`、`useMemo`、`useCallback`、代码分割、懒加载)
- [ ] 无直接操作 DOM、无内存泄漏 (清理 Effect、取消订阅)
- [ ] 国际化/无障碍 (ARIA、键盘导航、颜色对比度)

#### SQL/数据库
- [ ] 无 `SELECT *`，显式列出字段
- [ ] 无笛卡尔积、无全表扫描 (EXPLAIN 验证)
- [ ] 事务范围最小化、隔离级别合理、死锁预防
- [ ] 批量操作分批 (避免长事务、锁升级、Binlog 膨胀)
- [ ] 软删除/乐观锁/版本号等并发控制机制正确

### 2.3 测试覆盖
- [ ] 单元测试覆盖核心业务逻辑 (边界值、异常路径、Mock 外部依赖)
- [ ] 集成测试验证模块间交互 (数据库、Redis、外部 API、消息队列)
- [ ] 接口测试覆盖正常/异常/参数校验/权限/幂等/并发场景
- [ ] 测试用例命名规范 (`test_<功能>_<场景>_<预期结果>`)
- [ ] 测试数据隔离 (独立数据库/事务回滚/数据工厂)
- [ ] 无 Flaky Test (时序依赖、随机数据、外部依赖不稳定)

## 3. 性能与可观测性

### 3.1 性能考量
- [ ] 无明显性能反模式 (N+1 查询、大循环查询、未分页大列表、同步阻塞调用)
- [ ] 缓存策略合理 (Key 设计、TTL、穿透/击穿/雪崩防护、一致性保证)
- [ ] 数据库查询有索引覆盖、无全表扫描、分页使用游标/Keyset
- [ ] 异步/并发处理合理 (线程池/协程池大小、背压控制、超时重试)
- [ ] 资源释放及时 (连接、文件句柄、临时文件、大对象)

### 3.2 监控埋点
- [ ] 关键业务指标已埋点 (QPS、延迟 P50/P95/P99、错误率、业务计数器)
- [ ] 分布式追踪完整 (Trace ID 透传、Span 语义标准、采样策略)
- [ ] 健康检查端点完整 (`/health`、`/ready`、依赖检查)
- [ ] 告警规则覆盖核心指标 (阈值合理、Runbook 链接)

## 4. 部署与运维

### 4.1 配置管理
- [ ] 环境变量/配置文件无硬编码、敏感信息外部化
- [ ] 配置变更有文档记录、版本化、回滚方案
- [ ] Feature Flag 用于渐进式发布、灰度控制

### 4.2 迁移与兼容
- [ ] 数据库迁移脚本已测试 (正向/逆向、大表在线变更策略)
- [ ] API 版本兼容策略明确 (Header/URL/参数版本、弃用时间表)
- [ ] 数据迁移脚本幂等、可重入、进度可查、失败可重试

### 4.3 运维友好
- [ ] 启动/停止/重启优雅 (信号处理、连接排空、任务完成等待)

## 附录：常见问题速查表

### 致命错误 (必须修复)
| 类别 | 典型错误 | 检查方法 |
|------|----------|----------|
| SQL 注入 | 字符串拼接 SQL | 搜索 `f"SELECT`、`%s` 拼接、`execute(` 非参数化 |
| XSS | `dangerouslySetInnerHTML`、未转义输出 | 搜索 `dangerouslySetInnerHTML`、`v-html`、模板引擎未转义 |
| 权限绕过 | 缺少资源所有权校验 | 检查所有写接口是否校验 `resource.owner == current_user` |
| 敏感信息泄露 | 日志打印 Token/密码/手机号 | 搜索 `log.*password`、`log.*token`、`log.*phone`、`print(` |
| 死锁 | 多表更新顺序不一致 | 检查事务中多表更新顺序是否固定 |
| 内存泄漏 | 订阅未取消、大对象缓存无 TTL | 搜索 `addEventListener` 无 `remove`、缓存无 TTL/大小限制 |

### 性能陷阱
| 场景 | 症状 | 优化方向 |
|------|------|----------|
| N+1 查询 | 列表接口查询数 = N+1 | `joinedload`/`selectinload`/批量查询 |
| 大事务 | 锁等待超时、主从延迟 | 拆分事务、异步补偿、乐观锁 |
| 无索引全表扫描 | 慢查询日志、EXPLAIN type=ALL | 添加联合索引、覆盖索引 |
| 缓存击穿 | 热 Key 过期瞬间 DB 压力飙升 | 互斥锁重建、永不过期+异步更新 |
| 连接池耗尽 | "Too many connections" | 调整池大小、检查泄漏、缩短事务 |

### 安全清单 (OWASP Top 10 映射)
| A01 访问控制失效 | 资源级权限、所有权校验、API 网关鉴权 |
| A02 加密失效 | TLS 1.3、敏感字段加密存储、密钥轮换 |
| A03 注入攻击 | 参数化查询、输入验证、输出编码 |
| A04 不安全设计 | 威胁建模、安全设计评审、最小权限 |
| A05 安全配置错误 | 基线核对、默认密码修改、调试端口关闭 |
| A06 易受攻击组件 | 依赖扫描、SBOM、及时升级 |
| A07 认证失效 | MFA、强密码、会话管理、JWT 短过期+刷新 |
| A08 完整性失效 | 供应链安全、镜像签名、依赖校验和 |
| A09 监控失效 | 结构化日志、关键操作审计、实时告警 |
| A10 SSRF | URL 白名单、内网访问限制、出口防火墙 |
