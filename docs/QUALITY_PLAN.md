## 4. 缺陷管理

### 4.1 严重度分级

| 级别 | 定义 | 响应时间 | 修复时限 | 示例 |
|------|------|----------|----------|------|
| **Critical (P0)** | 核心功能不可用/数据丢失/安全漏洞 | 15 分钟 | 2 小时 | 数据抓取全失败、SQL 注入 |
| **High (P1)** | 重要功能异常/性能严重劣化 | 30 分钟 | 4 小时 | 单接口 500、抓取成功率 < 90% |
| **Medium (P2)** | 非核心功能异常/体验问题 | 2 小时 | 1 天 | UI 对齐、非核心接口报错 |
| **Low (P3)** | 优化建议/文档/技术债 | 1 周 | 下个迭代 | 代码规范、注释缺失 |

### 4.2 缺陷生命周期

```
新建 → 确认 → 分派 → 修复中 → 验证 → 关闭
  ↓                              ↑
拒绝/重复/延期 ←───────────────┘
```

### 4.3 零缺陷发布标准

- **阻断发布**: 存在 P0/P1 未解决
- **允许发布**: 仅 P2/P3，且有规避方案
- **发布后 24 小时**: 必须验证无回归

### 5.1 编码规范

| 语言 | 规范 | 工具 | CI 强制 |
|------|------|------|---------|
| **Python** | PEP 8 + Google Style Docstring | black + flake8 + pydocstyle | ✅ |
| **TypeScript** | Airbnb + Prettier | eslint + prettier | ✅ |
| **Dockerfile** | Hadolint | hadolint | ✅ |
| **YAML** | Yamllint | yamllint | ✅ |

### 5.2 代码审查清单

- [ ] 功能实现正确，符合需求
- [ ] 单元测试覆盖新增/修改代码
- [ ] 无硬编码密钥/敏感信息
- [ ] 错误处理完善，日志可追踪
- [ ] 性能无明显退化
- [ ] 文档/注释同步更新
- [ ] 无明显安全隐患 (SQL注入/XSS/路径遍历)
- [ ] 依赖更新有必要性，版本锁定

## 7. 工具链配置

### 7.1 CI/CD 质量门禁

```yaml
# .github/workflows/ci.yml 关键质量门禁
- flake8 .              # 语法/风格检查
- black --check .       # 格式化检查
- pytest --cov=80%      # 覆盖率门禁
- trivy fs .            # 漏洞扫描 (Critical/High 阻断)
- trivy config .        # 配置扫描
```

### 7.2 本地开发工具

```bash
# 预提交钩子
pre-commit install

# 本地运行完整检查
make check  # 等价于: flake8 + black --check + pytest --cov=80%

# 本地安全扫描
trivy fs . --severity CRITICAL,HIGH
```
